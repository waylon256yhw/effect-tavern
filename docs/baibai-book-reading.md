# 读表记录：柏宝书（ST-BaiBai-Book），生态里做对了结构的那一个

2026-10-18。读了 baibai-git/ST-BaiBai-Book（commit 21f7488，2026-10-16，版本 1.3.2；浅克隆只拿到最近 50 个 commit，2026-07-07 到 10-16）。它是 SillyTavern 的记忆扩展，社区里与"数据库"（`docs/memory-table-reading.md`）解决同一个问题：长程游玩里的摘要、状态、时间。前一份是 24.5 万行、13 个 agent、浏览器里跑 SQL；这一份 2.8 万行源码（`src/`，不含 dist），Vue 3，单作者，9 个 vitest 文件加 3 个回归脚本，代码注释写"为什么"。它是同一代材料里工程直觉最好的一份。

读法同前（§0 先分三堆，再逐条），但这份材料的意义不在"它缺什么"，在它**独立走到了和本项目同一个结构**：每楼一条事件，状态是事件的折叠，删一条就少折一条；压缩只压叙事文本，不碰状态。这是 memU 之外第二个外部参照，而且是生态内部的。

## 0. 站高一点

### 0.1 它是什么

| 部分 | 体量 | 内容 |
|---|---|---|
| `src/memory/` | 27 个文件，约 1.3 万行 | 类型、引擎、回放（apply）、注入、时间标签、换对话、提示词 |
| `src/memory/prompts/*.txt` | 72 KB 摘要 + 21 KB 总结 + 24 KB 二次总结 + 18 KB 协议 | 全部提示词文本，`{{宏}}` 填充 |
| `src/memory/vector/` | 9 个文件 | 查询重写、embed、rerank、索引对账、召回；向量库是另一个 ST 服务端插件"柏宝库" |
| `src/pages/`、`src/components/` | 约 1 万行 Vue | 摘要森林、物品、NPC、场景、变量、设置六个页面，楼层面板 |
| `PUBLIC_API.md` | 13 KB | 只读 JS API、`/bbs-get`、宏；带 `coverage.complete` |

核心模型三句话（`types.ts` 文件头原话的压缩）：

1. **叶子挂在消息上**：每条 AI 楼的 `extra.bbs_leaf` 存一段摘要正文加一份结构化增量 `delta`（物品 add/update/remove、NPC、场景、计划 add/update/resolve、主角档案补丁、变量路径命令）。
2. **状态是派生的，不落盘**：`deriveMemory(chat, upTo)` 按楼层物理顺序扫所有有效叶子，fold 它们的 delta，得到物品、NPC、场景树、计划、变量树。删叶子、翻页到别的 swipe、标番外，那条 delta 就不再重放，状态自动回退。id 确定性（`item:名`、`scene:路径`、`plan:叶子id#序号`），重放幂等。
3. **压缩节点只压文本**：L0 叶子攒够 12 条压成一条 L1（保留最近 3 条不压），6 条 L1 压 L2，3 条 L2 再向上；压缩节点存 `chatMetadata`，`childIds` 指向下层，**不带 delta、不参与状态重放**。注入时为每个滚出窗口的叶子选"最高的、完好的、能整体代表它的节点"。

两条通道注入主模型：历史摘要（depth 9999，带代码算出的相对时间"三天前"）和当前状态（depth 1 或 2，按在场分档：在场 NPC 全量，同区域名加身份，不在场只有名；物品按当前地点可达与否分两档）。另有 depth 0 一条固定提示，要求主模型每段正文首尾输出 `<bbs_start>`/`<bbs_end>` 绝对时间。

时代：Horae 的后继（能从 Horae 迁移，查询重写照抄 Horae），副 API 默认指向硅基流动，提示词按 2025 到 2026 年 Gemini / DeepSeek 一类副模型的掉格式方式打补丁；2026-10-10 "移除预填充"，与本项目同月发现的"当前 Claude 拒绝 prefill"一致。

### 0.2 参照：和 shujuku 面对同一面墙

两份材料面对的是同样四个缺位（消息是字串、状态没有主人、请求形状不可编程、回合没有阶段）。shujuku 的回答是在宿主旁边再造一个宿主（零层、13 个 agent、SQL）。柏宝书的回答是**把宿主当成一个只会存键值对的文件系统**：消息 extra 是事件日志，chatMetadata 是索引，派生全在内存里算。它没有造宿主，所以体量小一个数量级；但它仍然要为宿主的每个缺位付一份税，下面第一堆就是税单。

### 0.3 第一堆：对屎山的兼容补丁

去掉 ST，这些没有一个有存在理由。它们占了引擎与回放代码的大半。

- **ST 没有日志树。** 叶子要记录自己生成时的 `swipe` 页码，因为 ST 生成新 swipe 时 `structuredClone` 旧 extra 会把上一页的叶子复制进新页；于是有 `leafValid`（当前页有效）与 `leafIntact`（物理存在）两个判定，翻页时压缩节点要"降级拆解"而不是删，删叶子时要 `pruneBrokenComps` 把整条祖先压缩链全删（等于上层全部重做）。本项目：swipe 是兄弟节点，压缩是按区间缓存的派生视图，这一整类不存在。
- **回合没有阶段。** 摘要是 GENERATION_STARTED 事件上挂的异步任务，于是有生成拦截器：数"洞"（末楼之前没摘要的楼），0 个放行，1 个等在飞的摘要，多个就 `abort` 并用 `/sendas` 往聊天里插一条"柏宝书：请先补摘"的提示楼，再用哨兵字符串防止这条提示楼下一轮被当成真 AI 楼。开场白有专判：卡的开场白不是本插件的提示词生成的，没有时间标签，若放任首轮生成，主模型和开场白摘要会各编一个开场时间；解法是先摘开场白再放行。本项目：record 是回合的一个阶段，开场是卡数据带 `opening` 效果，时间的初值是卡的一个字段。
- **历史不是视图。** 滚出窗口的楼用 `/hide` 踢成 `is_system`，加私有标记 `bbs_hidden` 区分"我们藏的"与 ST 自己的系统楼，`/hide` 失败回退直接写 `is_system` 再 `reloadCurrentChat`。叶子"生成与使用解耦"：所有楼都提前生成叶子，只有所在楼被藏了才注入。本项目：折叠边界就是这条线，历史按阶段渲染。
- **请求形状不可编程。** 四个 `setExtensionPrompt` 槽位（历史 9999、状态 1/2、时间标签 0、召回另配），每段注入首尾套"私密简报｜仅你可见……不要输出简报的标签、字段、编号……不要提及记忆系统"和一段 300 字的结束语，教主模型把简报当过去而不是上限、不要把目的地当已到达、不要把旧伤当不变。这是在同一条 messages 里混叙事者与账本，再用文字求模型分清。本项目：叙事者看转录稿，导演看事实账本，是两个视图。
- **消息是字串，只能往正文里塞结构。** 时间标签留在正文里（真删会失同步），靠正则在显示层藏；摘要后把本楼物品与变量的净变动写回正文 `</bbs_end>` 之后（`<bbs_items>`、`<bbs_vars>` 旁注），让窗口内全文楼层被主模型看到"这笔已结算"；FAQ 原话："手改物品的正统方式就是改正文旁注"，系统反向解析回叶子 delta。要改状态得改散文，这是整份材料里最能说明缺位代价的一处。本项目：节点有 `reply` parts、`products`、`answers`、`adjust`，`setField` 是对节点的动作。
- **副 API 自带一套通道管理**：多渠道、按任务指派、超时 180 秒、重试、主 API 回退时"不带聊天历史"。本项目：阶段绑定连接。
- **没有结构化输出。** 让模型先写 `<thinking>` 核查块再写 JSON，`extractJsonObject` 从文本里抠，失败重试，"AI 道歉或掉格式"是一类错误。本项目：强制 schema。
- **换对话丢记忆。** `carryover` 新建聊天时在 #0 挂一片"种子叶子"：text 是旧局合并摘要，delta 是把当前全部状态编码成全量 add；再造一个 L2 节点收纳它，向量库把旧局快照成 bundle。它复用了回放管线，没有特殊载体，是补丁里最漂亮的一个。本项目：路径就是路径，从任一节点分支是原生的；"没有输入与正文、只有产物的根节点"就是上一份记录 §6 第 2 条，种子叶子证实了那个形状。
- 与生态共存：Horae 迁移、`summaryOnlyMode`（卡自带变量系统时不注入状态、不写旁注）、按世界书排除、自定义清洗标签（思维链、状态栏）、正则与预设格式打架的修复。本项目：卡自己的变量系统就是产物，没有第二套要共存。
- 公开 API 带 `coverage.complete` 与 `missingAiFloors`，诚实地告诉消费者"状态有洞"。洞来自摘要异步于生成；阶段模型里按构造没有洞。

### 0.4 第二堆：方向错误，不是环境所迫

比 shujuku 少得多，而且多半是**体量**问题而不是**方向**问题。

- **72 KB 的摘要提示词。** 物品三条准入、消耗品、严禁重复结算、随身与存放、场景准入与复用、NPC 准入反例、伤情局部更新协议（`conditionPatch` 用 c1/c2 编号 replace/add，每条带 `evidence` 原文短引）、NPC 定位证据（非空 `location` 必附 `locationEvidence` 连续原句，"程序只校验编号、类型和引文存在，不替你判断引文是否真正表示恢复"）、好感五档"默认保持，跨档才更新"、关系线保留、生活小档案铁律、三套时间规则。每条规则都对应一个用户实测过的失败，每个失败长成一段。引文校验是便宜又真实的技术（grounding by quotation），但 72 KB 规则加 18 KB 核查清单本身说明：在没有 schema 的通道上，质量只能靠文字堆。本项目的立场：harness 的问法是带 id 的短默认 fragment，卡与玩家按 id 覆盖；规则文字属于玩家层与卡，不属于代码。
- **越狱段。** 一个叫 NVWA、"源氏集团创建"的虚构模型身份，附一份写得像厂商系统提示的成人内容与安全边界说明，挂在每次摘要请求的 system 第一条。它比 shujuku 的假 assistant 应答体面，但同一类：用身份谎言换副模型不拒答。拒答是 provider 层的事。
- **生活小档案的三层投放**（pinned / active / archive）加 `topics` 与 `anchors` 关键词，从最近六楼正文里撞词触发。这是给模型写的行重新发明一遍世界书扫描器。上一份记录已定：模型写的行走 lookup 的枚举（一次分类），不做关键词。
- **召回的查询重写强制启用、无降级**：每轮生成前多一次 LLM 调用把剧情改写成 INTENT 加恰好 5 条 Q（1.3.1 从"1 到 3 条"改回 5 条，因为多路 RRF 融合需要条数），失败则整次召回取消。阈值 0.8 / 0.9、起召门槛 30 楼、候选 20、全文 2 条。它是 Horae 的管线，比 memU 终态（embedding 加 BM25 一遍过）多了重写与 rerank 两跳；不算错，是上一份记录 §6 第 5 条那个 ceiling 的一种实现。有一个值得记的设计：**索引的是叶子摘要，命中后发回的是原文**（rerank 够高发 `mes_full`，不够只发摘要）。摘要做键、原文做值，比对原文直接 embed 便宜也准。

### 0.5 第三堆：我们已经有的，它也有

这一堆是这份材料的价值所在：不是"我们有更好的"，是"它独立做出了同一个"。

| 它 | 我们 | 备注 |
|---|---|---|
| 叶子 delta 按楼序 fold，状态不落盘，删叶子即回退 | 日志树沿路径 fold，节点只存模型输出与种子 | 同一思想；它要为 swipe 加页码戳，我们是兄弟节点 |
| 压缩节点只压叙事文本，不带 delta，不参与重放 | notes 的折叠与状态的 fold 是两条线 | 同一切分 |
| 摘要请求里的状态取 `deriveMemory(chat, beforeIndex)`，重摘早期楼不泄漏未来 | 装配是纯函数，任一节点的请求从路径前缀重算 | 同一性质 |
| 选"最高的完好节点"代表一段 | 前缀折叠按区间缓存 | 它的压缩节点持久化，叶子一变整条祖先链删掉重做；我们是派生视图，失效免费 |
| 物品 / NPC / 场景 / 计划 / 主角 / 变量 | 产物：text / list / record / table，上限与过滤由代码施加 | 它是六个内置强约定；我们是一个词表，harness 给默认，卡补丁 |
| 变量用路径命令 set / assign / remove / add（MVU 式），物品用全值 add / update | 效果词表 set / add / event；带 key 的表收 upsert / delete 是 ceiling | 它在同一份代码里两种都用了：自由树用操作，固定表用全值。印证那个 ceiling 是真实取舍 |
| 计划 resolve 带 outcome（done / cancelled / failed）与原因，近期已了结 5 条注入"防重复推进" | feed 回喂 Known / Current；list 产物里路径上已有的条目由代码丢弃 | 同一个病（模型把已结算的再结算一遍），两种药 |
| NPC 好感双轴五档，"默认保持，只有充分新依据才跨档" | 读数：record 阶段的选择题，选项带效果，代码施加 | 它是 harness 内置的一个读数；我们读数由卡声明 |
| 在场分档：NPC 与物品按场景树祖先链决定注入多少 | lore 层按 Cond 开窗；table 产物的 `filter` 是对行的 Cond | 它的分档是 `location ∈ 当前路径祖先链` 这一条 Cond 的硬编码 |
| 年龄存原话加记录时刻 `ageTime`，展示时按故事时间推算 | 派生不存储 | 同一直觉的小例子 |
| 公开 API：`getSnapshot({floor, at: before|after})`、`getVar(path)`、`getHistory({before})` | 节点投影：turn、折叠后状态、本轮事件、揭示正文；`GET /nodes` | 同一形状。它的 before / after 是我们的父节点与本节点 |
| 副 API 按任务指派 | 阶段绑定连接 | |
| `summaryOnlyMode` | 产物按 id 开关 | |

### 0.6 分堆之后剩下什么

三堆拿掉，剩下的不是机制，是两个确认和一个默认值。

1. **结构被独立复现。** 生态里工程最好的记忆扩展，在没有日志树、没有阶段、没有结构化输出的宿主上，用消息 extra 当事件日志，做出了"事件 fold 成状态、压缩与状态分离、派生不落盘"。它为此付的税（页码戳、祖先链整删、拦截器、提示楼、旁注反解析、种子叶子）正好是本项目结构免掉的那些。这比 memU 更近的一个证据：同一个社区、同一类玩家、同一些卡。
2. **"模型写的记忆进 lookup"与"不开回合的 record"再次成立。** 它的向量召回和种子叶子分别是这两条在 ST 上的形状。
3. **故事时间。** 它的做法是材料里最成熟的一处：叙事者在正文首尾给出绝对时刻（不做加法，只写时刻），代码算相对时间与年龄，`timeRel.ts` 有独立测试。shujuku 让模型算 `prev + elapsed` 会漂，是第二堆；这个不漂。三问过一遍：不是 ST 补丁（时间分叉在任何 harness 里都会发生）；不是 vibe（写时刻、派生差值，有测试）；我们有机制没有默认（narrate 的输出形状由卡声明，可以是散文加一个 `time`；feed 产物沿路径取最新）。所以它落为一个**默认值候选，不是协议改动**：harness 的默认产物里多一个 `time`（text，feed，关着），折叠视图里的相对时间标签是日后视图的事。先记下，等某张模板卡需要时再开。

## 1. 逐条对照

下面只记对设计有信息量的细节，分堆已在 §0。

### 1.1 回合与触发

| 机制 | 它 | 我们 |
|---|---|---|
| 摘要时机 | 玩家发消息时摘"上一条 AI 楼"；翻页 / 重生成时跳过末楼摘再前一条；编辑、删除只刷新不生成 | record 是本轮的阶段，对本轮正文 |
| 积压 | 洞 0 放行，1 等，多个拦截并插提示楼 | 无洞 |
| 批量补摘 | 多楼切块一次请求，**只产 summary 与时间，不产结构化 delta**（"跨多楼顺序难保证"），块失败退回逐楼 | 导入文本按段跑 record，产物挂在根节点，段序即顺序 |
| 番外楼 | `bbs_omit`：不摘、不藏、不重放、不注入、不进时间线 | 不进转录稿的输入是 aside；一整轮要剔除是分支 |
| 重摘 | 带原摘要再请求；正文编辑不自动重摘（页码不变），要手动 | edit 是兄弟节点，record 重跑 |

### 1.2 摘要请求喂了什么

system 依次：越狱段、角色卡、persona、激活的世界书（都包在"只读参考，不要抄进 summary"的壳里），然后规则正文；user 是：历史摘要（截止本楼之前）、当前时间地点、主角档案、物品与近期物品变动、场景、NPC（带在场标记）、未了结计划、近期已了结、局势卡、生活小档案、变量状态加含义加规则、本轮正文（每行带 `[M楼-P段]` 编号供引证）；最后再一条 system 放核查清单。输出：`<thinking>` 块加一个 JSON。

对照我们的 record：Known / Current 行加本轮正文，问法是产物的 `text`，输出由 schema 定。它的"世界书作为摘要背景"对应我们 record 看得到本轮 disclosure。

### 1.3 注入与省 token

- 历史：每个滚出窗口的叶子由最高完好节点代表；带相对时间前缀；参照点是正文标签里的最新时刻，不依赖是否已摘。
- 状态：时间（公历带周几）、地点、局势卡（situation / participants / tension / pendingBeat，"隐性氛围约束，不要点破"）、生活小档案（撞词才出现）、主角档案、场景树（当前加祖先链详细，其他只名）、物品两档、NPC 四档、未了结计划、近期已了结、变量（只发含义，**不发规则**："主模型看到何时怎么改会误以为要在正文里输出"）。
- 变量的含义与规则拆成两段、分别给主模型与副模型，是"叙事者与导演看不同视图"的手工版。

### 1.4 时间

- 主模型每段正文首尾写 `<bbs_start>` / `<bbs_end>`，要求可定位到某一刻，禁"稍后""某天"，古风可用纪年时辰；开篇无锚点时"自行设定一个符合世界观的起始时刻"。
- 叶子存 `timeStart` / `timeEnd`；无标签时让副模型补。
- 相对时间（昨天、三天前、周几）、年龄推算由 `timeRel.ts` 算，有测试脚本。
- 计划的 `createdTime` / `targetTime` 是故事内时间字符串，允许模糊值。

### 1.5 向量召回

阻塞在生成前：查询重写（必需）→ 各 Q 各自 embed → 当前 chat 加各 bundle 多路检索、RRF → rerank（INTENT 做 query，未配则跳过）→ 全文档（rerank ≥ 0.9，前 2 条发原文）与摘要档（embedding ≥ 0.8）→ 按叶子去重并排除窗口内已全文的 → 注入。缓存键是最新 user 楼加上一条 AI 楼加参数，翻页重生成不重算。索引增量对账：摘要文本 hash 变才重 embed，只有原文或时间变只刷 payload。

### 1.6 换对话与导入

- carryover：种子叶子（见 §0.3）加 L2 收纳节点加窗口内楼层原样搬运加向量 bundle。
- 导入旧总结：一条 `imported: true` 的原子压缩节点，带 `importedFloorStart / End`，范围内楼层不再补摘、整段隐藏。

## 2. 对协议的要求

按 §0.6。这份材料对协议的净贡献是零条改动，一条默认值候选，两条确认。

**默认值候选**

1. harness 默认产物加 `time`（text，feed，默认关）：叙事者或 record 写绝对时刻，折叠沿路径取最新，Current 行带给下一轮。相对时间标签是视图层的派生，日后随客户端定。不改 `Product` 的 schema。

**确认（已在协议里）**

2. `recall` 产物与 lookup 同路（上一份 §6 第 1 条）：它的向量召回是这条的检索实现。补一句 ceiling 的实现细节：检索键用模型写的行，命中后送原文而不是行本身。
3. 不开回合的 record（上一份 §6 第 2 条）：它的种子叶子与导入节点是同一形状的两个实例，根节点只有产物没有输入与正文。

**不进协议的**

4. 页码戳、祖先链整删、拦截器与提示楼、`/hide` 与私有标记、四个注入槽、私密简报壳、正文旁注与反解析、越狱身份、72 KB 规则、关键词投放层：§0.3 与 §0.4，没有对象。
5. 六个内置台账（物品、NPC、场景、计划、主角、变量）：是内容，不是机制；哪张模板卡需要哪几个，到时按产物声明，harness 不内置领域。
