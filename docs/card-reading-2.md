# 读卡记录二：一张重前端的 MVU 卡，与青空莉的角色卡工具链示例

2026-10-18。读了两份材料。一是一张女性向的 Character Card V3（`矢城弘直DK.json`，263KB）：纯聊天卡的内容，加 MVU 变量系统、七条正则、四段前端 HTML。二是青空莉（StageDog，MVU 与酒馆助手的主要维护者）仓库 `tavern_resource` 的 `示例/` 目录：一张示例卡《呕吐内心的少女》和它依赖的整条工具链（tavern_sync、tavern_helper_template、util/mvu、util/streaming、立即事件脚本、自动更新脚本），加一份给编码 agent 的 `AGENTS.md`。

第一份只读机制，不读内容，不上 live。第二份是生态里"最佳实践"的自述，读它是为了看一个清楚 ST 全部缺陷的人在 ST 上能把卡做到什么形状。

方法同前几份：对每个机制问"去掉它，分阶段回合模型里什么会坏"，坏的是需求，没坏的是包袱。这一次多了一个视角：不只看表达力，看**形状**。ST 是补丁上的补丁，它的很多机制不是需求，是三个结构决定缺位后被迫长出来的东西。看清缺位，补丁整类消失，不用一个一个审。

## 1. 两份材料是什么

### 1.1 第一张卡的体量

| 部分 | 大小 |
|---|---|
| 文件 | 263 KB |
| 四段前端 HTML（状态栏 32K、音乐播放器 14K、开场菜单 24K、脑内论坛 11K） | ≈ 82 KB |
| 16 条开场白 | ≈ 40 KB |
| 模型真正看到的文本（description、scenario、13 条世界书） | ≈ 20 KB |

其余是 V3 格式的重复字段与每条世界书 30 多个开关的元数据。

它的变量系统：3 个数值（好感度、欲望值、性欲值）、7 个字串（好感度描述、衣服、动作、正面心理、反面心理、准备行动、最深欲望）加世界的日期 / 时间 / 地点。模型在回复尾部写 `<UpdateVariable>` 里的 JSON Patch，正则从显示和提示词里剥掉，MVU 脚本解析施加，Zod 夹边界。四对正则的作用只是把同一段字分成"给模型看"与"给玩家看"。脑内论坛是关键词触发的世界书条目：玩家打一句暗号，模型整条回复变成固定格式的"帖子"，正则渲染成 HTML。两条 IF 线开场（地缚灵、半兽化）各配一条默认关闭的世界书条目，玩家选了那条开场要手动去勾。

### 1.2 工具链示例

| 环节 | 做什么 |
|---|---|
| tavern_sync | 本地 YAML 加文件夹是源码（`index.yaml` 用锚点复用条目元数据，正文拆成文件），`bundle` 编译成卡，`watch` 与酒馆实例双向同步 |
| tavern_helper_template | webpack + TS + Vue + pinia + zod；界面与脚本打包成 html / js 上传 CDN，卡里只留一行 `import 'https://…'` |
| MVU + mvu_zod | 模型写 JSON Patch（新增 `delta`、`insert`、`move`）；zod schema 校验、clamp，`transform` 算派生字段 |
| util/mvu.ts | pinia store 与楼层变量双向绑定，每 2 秒轮询 |
| util/streaming.ts | 隐藏酒馆原生楼层 DOM，插自己的，监听流式事件，边流边用正则从正文剪出 `<roleplay_options>` |
| 立即事件脚本 | 状态到阈值 → `injectPrompts` 注入隐藏关键词 → 世界书扫描激活条目 → 黏性 5 冷却 9999 保持五轮只触发一次 |
| 自动更新角色卡 | 卡从 URL 拉新 PNG 与更新日志 |
| AGENTS.md | 作者是接着浏览器 devtools 的编码 agent，代码热重载进酒馆看效果 |

它的前提与本项目相反：卡作者就是程序员，或用 agent 当程序员。本项目的对应物是自然语言编译那一步。但基础设施上它做的每一件事都在补 ST 的缺，这些缺正是本项目要原生提供的。

示例卡的 zod schema：一个数值（依存度），四个集合：近期事务（动态键 → 文本）、着装（六个固定键 → 文本）、称号（动态键 → {效果, 自我评价}，上限 ⌈依存度/10⌉ 由 transform 算）、物品栏（动态键 → {描述, 数量}，数量归零隐藏）。角色阶段用 EJS `<% if getvar < 20 %>` 切五段文本。交错频道是每回复必带的一段旁白嘲讽（≤100 字，yaml 代码块）。第二条开场白尾部自带 `<initvar>`，给出与第一条不同的日期、地点、依存度和物品。状态栏上有 +/- 按钮，玩家可直接改依存度。

## 2. 逐机制审视：第一张卡

| 卡里的东西 | 去掉后坏的 | 本项目的形状 |
|---|---|---|
| description、scenario、NPC、对话补充 | 虚构本身 | `fiction` 常量 fragment |
| 双语输出规则（标"最高优先级"） | 阅读体验 | 玩家层槽位 `language`。作者用咒语声明优先级，正是因为 ST 没有归属层 |
| "顺着玩家暗示推"的基调指令 | 基调 | 框架 `tone` 槽位 |
| 分阶段角色设定（好感度四段，把数字塞进提示词让模型查表） | 性格随关系演变 | 四条带 `when` 的 fiction 变体，模型不见数字（理卡已验） |
| 三个数值，模型以 JSON Patch 写新绝对值 | 数值演进 | `Field` + `Readout`：模型只选档，代码定幅度 |
| 好感度描述（模型写当前阶段名） | 无 | 删。它是好感度的派生，作者不信模型会读数才多要一个字段 |
| 衣服、动作、地点、日期、时间 | 连续性 | record 的事实，不是字段。被条件读到的才升格 |
| 正面心理、反面心理、准备行动 | 玩家想看角色暗面 | record 产物（内心话） |
| 最深欲望 | 无 | 常量，模型每轮抄一遍。删 |
| `<UpdateVariable>` + 剥除正则 + Zod 脚本 | 以上全部的载体 | 不存在：节点存结构化 parts |
| 脑内论坛（暗号 → 整条回复变格式化帖子 → 正则渲染） | 按需窥视内心 | 对节点的玩家动作：不新建回合、不进历史，向模型要一份结构化产物（主题、主导人格、四到六条跟帖各带人格 id 与告警标志），视图渲染。九个人格是数据 |
| IF 线开场各配默认关的世界书条目 | 分支开局改设定 | 开场白带初始效果；IF 设定是 `when` 读 `route` 的 fiction 变体 |
| 开场预览菜单 HTML | 选开场 | 客户端自带 |
| 状态栏 HTML，每楼一份 | 看状态 | harness 标准视图，作者声明喂哪些字段与产物 |
| 音乐播放器 | 氛围 | `view` 资产，与模型无关 |
| "对 AI 隐藏 / 对玩家显示"四对正则 | 无 | ST 单一消息字串的产物 |
| odysseia_trace 加密水印 | 防盗 | 生态问题，记一笔 |

ST 让作者额外做的事：七条正则（四条只为分流）；教模型写 RFC 6902 再用 Zod 兜它写错的数；多维护一个派生字段与一个常量字段；每楼渲染 46 KB HTML；用暗号短语做玩家动作、污染转录稿、事后删楼。

## 3. 逐机制审视：工具链示例

| 机制 | 去掉后坏的 | 本项目的形状 | 表达得了 |
|---|---|---|---|
| zod transform 算派生值（依存度 → 阶段名；称号数上限；数量归零隐藏） | 派生要由代码算、不问模型 | `when` 变体；上限与过滤是产物上的数据 | 阶段：是。上限 / 过滤：见 §7 规则一 |
| 角色阶段 EJS 控制流 | 性格随数值变 | 五条 `when` 变体 | 是 |
| JSON Patch 新增 `delta` | 模型写绝对值不准 | 读数选项带固定增量 | 是。他让模型报 ±3~6，本项目让模型只选档 |
| 变量更新规则里每字段一条 `check` | 告诉模型怎么判断 | 产物的问法槽位 | 是 |
| 交错频道 | 固定点向模型要一样东西 | record 产物，文本形状 | 是 |
| `<roleplay_options>` + 点击即发送 | 选项玩法 | record 产物，列表形状；视图动作"作为 act 发出" | 形状见 §7 |
| 立即事件四跳链 | 到阈值导演一次事件 | lore `offer` 读状态 + 导演 MUST + 条目的"几轮前触发过 / 触发过几次"派生状态 | README 方向 2 已规划的派生状态，加一个计数 |
| 开场白自带 `<initvar>` | 不同开场不同初始状态 | 开场白带初始效果 | **否**，两张卡撞到同一处 |
| 状态栏 Vue 从 CDN 加载进每楼 iframe，pinia 轮询楼层变量 | 看状态 | 标准视图，长寿实例，推节点投影 | 方向 5 |
| 状态栏 +/- 直接改依存度 | 玩家手动修状态 | 视图发出玩家动作 → 对节点的 `set` | **接口未定**，"对节点的动作"第二个实例 |
| 流式楼层界面边流边剪标签 | 自定义视图要流式 | 流式事件按 parts 分道，产物不埋在正文里 | 对流式协议的一条要求 |
| 变量五种作用域 | 持久化的归属 | 楼层 = 节点折叠；角色 = 玩家 forCard；脚本 = 插件设置 | 是 |
| MVU 快照 / 重演楼层 | 状态与楼层不同步时修复 | 日志树折叠，天然一致 | 不需要 |
| 关闭的"向量化"空条目当 ===开始 / 结束=== 分隔线 | ST 世界书没有分组 | 归属区就是分组 | 不需要 |
| YAML 锚点复用 30 个字段的元数据 | 每条目都要抄坐标 | 条目没有坐标 | 不需要 |
| 文风（一整页结构化描述，第一人称） | 文风 | 框架 `style` / `pov` 槽位，玩家可覆盖 | 是 |
| 自动更新角色卡 | 分发与版本 | 卡协议带版本与来源 | 记一笔 |

## 4. 从形状看：三个缺位，四类扫描器

| ST 的缺位 | 被迫长出的东西 | 本项目的一个结构决定 |
|---|---|---|
| 一条消息就是一个字串 | 正则层（显示 / 提示词两套）、占位符、尾部命令块、流式里剪标签、`formatAsDisplayedMessage` | 节点存带类型的 parts |
| 状态没有主人（楼层 / 聊天 / 角色 / 全局 / 脚本五处可写，模型、脚本、UI 都能改） | JSON Patch、Zod 纠错、stat_data / display_data / delta_data 三份、快照 / 重演 | 状态是日志树的折叠结果 |
| 请求形状不可编程，只有"整个提示词"一种调用 | 一切变成提示词文本：咒语、"最高优先级"、EJS 控制流、关键词当消息总线、用 generateRaw 跑旁路任务 | 阶段各自配置请求形状，代码掌握循环 |

四类扫描器（正则、关键词、EJS、JSON Patch）全是在字串上找结构。有了结构，扫描器没有对象。

## 5. 收束：多对一

| ST 里的 N 个 | 本项目的 1 个 |
|---|---|
| 提示词来源的坐标系：卡四字段、世界书 before / after_char、深度 + 角色 + order、预设条目 order、作者注释、`injectPrompts`、`depth_prompt` | Fragment（文本、区、条件）。三个区：玩家 / 卡框架 / 虚构。顺序是文档顺序。"放在历史之后"是回合装配的一个字段，不是坐标 |
| 三种模板语言：ST 宏、EJS、STScript | 零种。条件是封闭树；`{{user}}` 是 persona 槽位的引用；状态渲染是 harness 的事；随机数不进提示词 |
| 世界书条目 30 多个旋钮 | 两个条件 `unlock` / `offer`，加代码维护的派生计数。"玩家聊到了"是查找阶段的一次分类 |
| 关键词当消息总线 | `offer` 直接读状态 |
| 变量五种作用域 | 节点折叠、玩家 forCard、插件设置 |
| 五种扩展运行时：正则、STScript、助手脚本、助手前端（每楼 iframe）、服务端扩展、提示词模板、MVU | 两个扩展面：卡协议（数据 + 视图）给创作者，harness 插件（代码）给开发者 |
| 酒馆助手约 25 个 API 文件 | 视图拿三个：读节点投影、发玩家动作、订阅事件。inject / generate / worldbook / preset 对视图不存在：视图永远碰不到模型 |
| generate / generateRaw 两个整体口子，旁路任务靠脚本自己调 | 阶段。总结是压缩（派生视图）；旁路索要是 record 产物 |
| 三种制品按名字绑定（卡、世界书、预设），运行时从 CDN `import` 脚本，自动更新拉新 PNG | 一份卡文档（lore 在卡里，视图包随卡带哈希），一份 enhancer（归玩家）。运行时不加载远程代码 |
| 生成按钮的多种模式：swipe、regenerate、continue、impersonate、编辑楼层、群聊轮次 | 节点上的玩家动作：兄弟节点、要产物、改字段。群聊是 fiction 写了一群人 |
| 两套作者界面：ST 表单，或 文件 + tavern_sync + webpack + agent | 一套：自然语言编译成数据，GUI 是数据的视图 |

十来个坐标系、三种语言、五种运行时、二十多个 API，收成一种片段、一棵条件树、一种节点、两个扩展面、三个视图 API。

## 6. 不该收束的

收束砍的是实现的多样性，不是需求的多样性。两份材料里真实的多样性在三处：

- **固定点索要的长尾。** 交错频道、选项菜单、脑内论坛、事务表、背包、内心话。每张卡要的不一样，产物必须是声明项加封闭的形状词表，不是 harness 预装几个。
- **作者视图。** 状态栏、论坛、电话界面。沙盒加消息协议，样式完全是作者的。
- **玩家对措辞的手感。** 这个生态的用户会调文字，`asks` 按 id 覆盖就是给这个留的。

一处要警惕收得过头：深度 0 / 深度 1 注入在两份材料里都重度使用（文风、变量规则贴在回复前）。它是真实需求"这段话要离回复近"，用回合装配的一个字段表达它，不能因为讨厌 depth 坐标连需求也删了。

## 7. 跨文件的规则

- **带形状的提取物，不是字段。** 示例卡的 schema 里决定性的数只有一个（依存度），其余全是集合，没有一个被条件读过，只被显示和喂回。它们是 record 阶段按声明形状提取的事实，即模型三件事里的第三件。第一张卡的七个字串、脑内论坛的帖子结构、交错频道、选项菜单、事务表、背包，全在这一类。缺的是产物的**形状词表**，封闭几种：一段文字、文本列表、固定键记录、带列的表（列只有文本与整数）。上限（最多 8 项、最多 ⌈依存度/10⌉ 个）与过滤（数量为零不显示）是产物上的数据，不是 transform 代码。是否回喂模型是产物上的开关，默认关：ST 把所有变量无差别塞回提示词，这两张卡里真正影响下一轮的只有那一个数。这是对 README 方向 1 遗留的"模型逐轮改写的文本字段"的正式回答：它们是产物，不是状态。MVU 的整个 zod schema 是在给提取物补 ST 没给的结构；结构给到节点上，MVU 没有存在理由。
- **开场白带初始状态。** 两张卡都要（IF 线设定、不同的日期地点数值物品）。`greetings: string[]` 改成带可选效果的对象，`Field` 加枚举类型给 `route` 这类东西。
- **对节点的玩家动作是一个此前没有的交互面。** 向节点要一份产物（脑内论坛）、改节点上的一个字段（状态栏 +/-）、钉住一条 lore。都不是新回合，不进转录稿，结果记在节点上可重放。ST 用假用户消息和暗号实现它，再删楼。
- **导演事件的"一次、持续 n 轮"不是新机制。** 立即事件的四跳链（脚本注入 → 关键词扫描 → 黏性 → 冷却）是方向 2 里"条目距上次露面几轮"再加一个"触发过几次"，`offer` 能读就够。
- **流式按 parts 分道。** 示例要用正则在流里找标签才能把选项渲染成按钮；本项目的产物本来是 narrate 之外的阶段产出，流式事件带阶段与产物边界，视图不解析正文。
- **工具链四件东西对应协议四项功能。** tavern_sync、webpack 模板、util/mvu、util/streaming 分别对应：卡是数据（无需同步）、视图包是卡的附件（无需外部构建约定）、节点投影（无需轮询绑定）、分道流式（无需剪标签）。它们是协议该直接提供的，不是要兼容的生态。

## 8. 对协议的要求

从这两份材料读出来、现有 schema 与设计尚未覆盖的，按层列出。

**卡协议（`Card` 数据）**

1. `Field.type` 加 `enum`（带 `options`），给 route、模式这类离散状态；`Cond.is` 已接受字串。
2. `greetings` 条目从字串改为 `{ text, do? }`，`do` 是现有效果词表。
3. `products`：声明的 record 产物。每项：`id`、问法（带默认文字的槽位，可按 id 覆盖）、`shape`（封闭词表：text / list / record / table）、`when?`、`feed`（是否回喂，默认否）、上限与过滤（数据）、视图绑定。卡给默认开哪些，玩家按条开关，enhancer 只能碰开关与问法。notes 本身可以是形状为 list 的默认产物。
4. lore 条目的派生状态作为可读路径暴露（距上次露面几轮、露面次数），`offer` 用现有 `path` 条件读。
5. `view` 附件的声明形状：包的哈希、绑定的字段与产物 id。实现仍按 README 顺序往后排。
6. 卡的版本与来源字段。

**节点与阶段协议（运行时 → 客户端）**

7. 节点投影：输入（通道标注）、各阶段的记录、回复 parts、产物、折叠后状态、本轮揭示、溯源；不含 fragment 正文。
8. 不经叙事者的玩家动作：swipe（兄弟）、改正文（兄弟，重跑 check / record）、改字段（记在节点上、折叠时作为效果重放）、要产物（挂在节点上）、钉住 lore（直接产生揭示）、选选项（作为 act 开新回合）。每一种在日志树里的落点要写明。
9. 流式事件：阶段边界、每个 part 的增量、产物各自的增量、结算后的状态、揭示。产物与正文是不同的道。

**视图沙盒协议**

10. 宿主 → 视图：节点投影、状态、产物、流式事件。视图 → 宿主：第 8 条里的动作。一个长寿实例，不是每回合一个 iframe；视图拿不到任何能触达模型的东西。
