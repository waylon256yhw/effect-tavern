# 互动小说阅读器：第二轮需求（重写一稿）

接着上一版设计稿做（主方案 A），这轮只补一个状态，顺带改四处小地方。还是那条规矩：手机优先，正文是产品，界面上不放解释用法的文字。

## 一、要补的状态：第一稿被第二稿替换

上一版把"一节写完"当成正文流完的那一刻。实际的顺序多两步：

1. 正文逐字流完。
2. 停一两秒到几秒：故事在检查这一稿（有没有违反这局的规矩，有没有漏掉这一节必须讲到的事）。读者看不到检查的内容，只看得到在等。
3. 大多数时候检查通过，接着再等几秒，附注（读数变化、线索、备注、建议）一起到达，这一节才算写完。
4. **少数时候检查不通过，故事把这一节从头重写一遍。** 第二稿和第一稿一样逐字流出来，流完再检查一次（最多重写这一次，第二稿不管怎样都算数），然后附注到达。第一稿被丢掉，它不是兄弟版本，之后看不到。

读者已经把第一稿读了二三十秒，有时读了一半，有时读完了正在等附注。要设计的是第 4 步读者看到什么：

- 怎么让读者知道"这一稿作废了、正在重写"，不用一个字的说明。
- 第一稿的文字怎么退场：立刻清空、淡出、还是留着变灰等第二稿顶上来。考虑读者可能正读到一半。
- 第二稿从哪里开始流：原位，还是第一稿下面。"流式不跳"那条规则在这里怎么守：读者的视口不能被顶来顶去，往上翻的时候不能被拉回。
- 第 2、3 步的等待（正文流完到附注到达之间）在上一版里没有样子，一起画出来：和发送之后、第一个字之前的那种等待是不是同一种。
- 重写中按停止，和正常输出中按停止一样：第二稿写到哪算哪，作为这一节的正文留下。
- 手机和桌面各一个，深色一个。

一个开放问题，请你判断并说理由：读者该不该能把第一稿留下来？现在的规则是不能。如果你认为该能，画出它长什么样，我们再看代价。

## 二、顺带改的四处

1. **停止**。上一版的假设 8 改成：等待中停止，这一节撤回、原句放回输入框（不变）；输出中停止，已写的部分作为这一节的正文留下，是真的一节，有附注；节上**不再有"继续"按钮**。"继续"是下面第 2 条里的一个片段。
2. **快捷片段**。"指令"改叫片段，是一张固定的短名单，每条有名字、文字、发给谁（角色还是导演）。默认几条：心声（填入 `⦅⦆`，光标停在中间）、继续、推进剧情、时间流逝、详细描写，后四条发给导演。选中只填进输入框，照旧不发送。读者以后能自己加，这次不画管理界面。
3. **改写和编辑不再有"保留后续的节"的勾选**。改写出来的新版本从这一节重新往下，和重来一样。
4. **钉住**。改对象：钉住的不是已经读到的线索（它已经在故事里了，钉不钉都记得），而是"故事里还没讲到的事"——一张短名单，每条一句话（比如"他左肩的纹身"），读者钉住一条，故事下一节就会讲到它。这张名单住在目录的"钉住"那一页；附注里线索旁边的图钉去掉。
