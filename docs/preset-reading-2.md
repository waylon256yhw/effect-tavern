# 读 preset 记录二：Reborn 2.3 / 小猫之神（魔咒式预设，带休眠的传输层）

2026-10-17。读了第二份生态 preset（`Reborn2.3.json`，434KB，为 Gemini 写；文件内标注 `小猫之神_3.7 Full`，版本信息条目写 `3.0-Preview-01`，三个名字指向同一作者的几代版本）。选它是因为它看起来是"一般意义上"的预设：作者文本是口语化的创作细则，不是代码。方法同 `preset-reading.md`：代码方向、语文方向、本项目的家；只描述结构，松绑类条目按机制一行带过。

依据：文件本身。SPreset 与 Tavern Helper 的语义按字段名、随文件携带的脚本源码与 `tavern-helper-reading.md` 推断。

## 2. 两层包装

### 2.1 第一层：ST 装配出的消息

```
system_instruction  ← #0–#14：身份替换、[World Settings] 与世界书、<char> 夹住的卡字段、[Player Role] 与 persona、伪对话"衔接"
                       （#0、#1、#3 等展开后几乎为空，各自仍是一条消息）
示范                ← #15
历史                ← #16，每楼已按深度剥过思维链与选项、远处只剩摘要
system × 24        ← #17–#48：创作细则各一条；最后一条要求全部输出走 game_content
tools               ← [game_content]，由 SPreset 并入
```

### 2.2 一轮的输出与回收

模型调用 `game_content`，`content` 里依次是：`<think_nya~>` 思考摘要（小猫口吻）、`<game>` 正文约 1500 字、`<summary>` 100 字、`<details>` 留言、`<options>` 三个选项。SPreset 把工具参数还原成普通文本落楼。显示时四块各自渲染成前端。下一轮 prompt 时同一楼层按深度失去思维链与选项，第 6 楼起只剩摘要。

### 2.3 依赖

| 依赖 | 断了会怎样 |
|---|---|
| 远程 JS 能加载 | SPreset 不存在：无工具绑定、无 squash、正则只剩原生一份。#48 仍要求走工具但工具不在，模型可能拒绝或直接输出 |
| `function_calling` | 关掉则工具不发，同上 |
| `<|merge|>` 标记 | 有人把它加回任何条目，squash 激活，整段对话变伪 JSON，#14 的"Pass"才有意义 |
| #44 `<game>` 与正则 | 正则没有针对 `<game>` 的条目，它只是正文的外壳 |
| #45 `<summary>` 与小总结1/2 | 关掉 #45 则深度 ≥6 的楼层被"小总结1"整条清空（正则匹配不到 summary 时的行为取决于实现） |

## 5. 跨文件的规则

- **"一般意义上的预设"也带传输层，只是关小了。** 作者文本占七成，但文件体积的 99% 是配置、模板与脚本，而且入口是一段从陌生域名加载的远程 JS。魔咒式与代码化不是两类 preset，是同一结构里作者文本与脚手架的比例不同。
- **历史之后是作者的默认位置，第三次。** 51 条里 #17–#48 共 32 条在历史之后，#14 的伪对话也紧贴历史之前。`main` 空着，`nsfw` 是"历史前最后一条"，`jailbreak` 是"历史后第一条"：槽名只有位置，与上份一致。
- **record 的三种产物第三次同时出现。** 摘要、菜单、模型书写字段（这里是思考摘要与留言）挤在正文尾部由正则拆开，各有各的显示与遗忘规则。三份材料三次相同，可以认为是生态的稳定形态，不是个别作者的习惯。
- **作者把"规则"写成对一个人设说的话。** 创作细则全部用对小猫撒娇的口吻（"写不够克扣小鱼干"），人设在 #2 和关掉的 #50 里。上份是"谁在写"与"怎么写"并存，这份把两者揉成一种语气。玩家层 fragment 的语文不该被强行规范成指令体。
- **配置复制再次出现，而且更重。** 正则两份（六条转义漂移），SPreset 配置两份（一份存成 prompt 正文）。生态用复制对抗宿主剥字段，代价是分叉。配置只有一个来源。
- **休眠配置带着为它写的文字。** squash 关着，#14 里"Gemini 只能说 Pass"仍在发给模型。文字与配置分离存放时，哪些文字服务于哪个开关没有记录，关掉开关文字留下。本项目里一个选项的文字与它的开关是同一个对象。
- **思考被要求做两次。** 原生 reasoning 开着，又要模型在正文里用人设口吻写一遍摘要给玩家看。作者要的是"让玩家看到角色在想什么"，这是展示需求，不是推理需求；它应是模型书写字段进视图，与 provider 的思考无关。
- **远程代码是预设的运行时依赖。** 一份预设文件通过 Tavern Helper 脚本从一个随机域名加载 JS 注入 ST 主窗口，全部传输层由此而来。这是"作者嫌宿主不够用"的极端形态，也是卡协议必须把视图关进沙盒、把逻辑关在卡外的理由。

## 6. 按归属方重切（2026-10-18）

第 3 节按"资产类型"分。这一节换尺子，按归属方分：harness（开发者，代码）、卡（作者）、玩家。51 条启用项：

| 归属 | 条目 | 形态 |
|---|---|---|

| harness 机制，槽位可改文字 | #45 小总结、#47 行动选项、#46 留言、#39 背景 NPC、#42 内心话 | 都是"在固定点向模型要一样东西"：record 阶段的产物。机制与 schema 归 harness，问法文字是一个槽位，harness 带默认文本，卡声明默认开关，玩家可开关 |
| 玩家层槽位 | #32 人称、#33 字数、#29 文风、#19/20 角色控制、#23/25/27 NSFW 风格、#34/35 转述、#37 我不是主角、#40/41 多视角、#13 用户角色 | "我想怎么读"。全是 `Player.global` 的 fragment，N 选一的是同槽变体 |
