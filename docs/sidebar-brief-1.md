# 骨架原型 brief 之一：双层左栏、顶条、对称折叠（2026-10-30，给 Gemini 出 artifact demo，#117）

`docs/sidebar-prototype.html` 是三轮 mock 挤进一轮的产物，这次拆成三份 brief，顺序是骨架 → 开局页 → 卡片详情页，因为骨架决定后两页拿到多宽的舞台。这是第一份，只管骨架。和 `docs/timeline-prototype-brief.md`、`docs/card-page-brief.md` 一样：只给数据、规则和约束，不给版式。要的是一个自包含的 HTML（数据内联、无依赖、无构建），桌面 1280 与 1152（72rem 断点处）和手机 390 都能打开，light/dark 用 `light-dark()` 和文末的 token。文件顶部用注释写清三件事：两层中段怎么滑、折叠怎么算列宽、顶条在每种舞台内容上长什么样。之后会移植到 Solid。

已经定下、不再重开的结论（#117 正文与 10-30 的两轮讨论）：不做独立主页；左栏是纯导航（卡 → 局），局级的东西全部上阅读器顶条；折叠就是 0 宽，不做图标轨；右栏只在舞台是阅读器时存在；建局只发生在"开始"那一刻，进卡、翻开场都不建局。

## 它是什么

一个安装的骨架，三块：

- **左栏**，两层，一次只显示一层。层 A 是卡架：这个安装的所有卡。层 B 是单卡工作区：这张卡的所有局。两层共用同一个顶条（返回 / 折叠）和同一个脚部（设置、主题、语言），切层时只有中段换，顶条和脚部不重绘、不跳。
- **舞台**，一次一种内容：阅读器（带右栏）、开局页、卡片详情页、Timeline、Inspector、Writing、Settings（后六种铺满舞台，右栏不在）。每种内容顶上一条顶条。开局页和详情页这次只画占位，有标题和返回即可，它们各有自己的 brief。
- **右栏**，阅读器的读数（状态表、Record、小剧场），只跟着阅读器出现。

左栏和右栏各能折叠到 0 宽，机制对称。

- `cards`：`GET /cards`，安装里的卡。summary 可缺。卡架层每张一行：标题、summary 一行截断、这张卡有进行中的局时一个点。

## 规则

**层。** 打开安装时在层 B，卡是 `current` 所在的卡；`current` 为 null 时在层 A。层 A 点一张卡进层 B：这张卡有局就开最近一局，舞台是阅读器；没有局舞台是开局页。层 B 顶条的"‹ 所有卡片"回层 A，舞台不变（正在读的局继续读）。层 A 的卡行上，别的卡有 busy 时那张卡显示点；层 B 的返回按钮旁，别的卡有 busy 时显示点。

**层 B 的中段**，从上到下：卡头（只有标题，点进卡片详情页；summary 不在这里，它在详情页）；故事搜索框（整行）；故事列表（星标的在前，其余按 updated 倒序，开着的高亮，busy 的行尾一个点，行只负责切局，没有星标按钮和 ⋯）；底部一枚整行的"＋ 新建故事"（进开局页，不建局）。脚部右端一个按钮开"本卡的故事管理器"（demo 只需 toast）。

**层 A 的中段**：卡搜索框（整行）；卡列表。脚部右端空着，不发明东西。

**脚部**（两层共用）：设置、主题切换、语言切换三个图标，左对齐。主题切换在 demo 里真的切。

**顶条**（舞台每种内容各一条，同一套语法）：

- 最左端：左栏折叠态时是"展开左栏"按钮，展开态时这个位置空着（折叠按钮在左栏自己的顶条上）。鼠标不跳：左栏顶条的折叠按钮和舞台顶条的展开按钮落在同一个 x 上。
- 阅读器的顶条：`卡名 › 局名`（局名截断）、人设 chip（点开人设选择，demo 用 toast）、**一枚**写法 chip（数组第一项，点开 Writing 页）、右端 Timeline、Inspector 两个图标，再右端是"折叠右栏 / 展开右栏"按钮。
- 其他内容的顶条：返回（回阅读器）、这页的名字；右端无右栏按钮。
- 顶条高度与左栏顶条相同，两者在同一水平线上。

**折叠。** 桌面网格 `左栏 | 舞台`，舞台为阅读器时内部再分 `阅读列 | 右栏`。左栏 15rem，右栏 19rem，画布 padding 与列间 gap 各 24px，正文列有 42rem 的 measure。折叠 = 那一列的轨道到 0、gap 到 0、内容 opacity 到 0，轨道宽度和 opacity 都做过渡（`grid-template-columns` 可插值），`prefers-reduced-motion` 下不过渡。两侧折叠态各自独立，记在 localStorage。注释里写清三个宽度下正文列实际得到多少像素：1152 全开、1152 收一侧、1312 全开。

**两层切换**：横向滑动，层 A 在左、层 B 在右，进卡向左推、返回向右拉，`prefers-reduced-motion` 下直接换。只有中段滑，顶条与脚部不动。

**手机（< 72rem）。** 没有左栏也没有右栏，没有折叠。顶栏左中右：☰ 开抽屉（抽屉里就是左栏的两层，含顶条、滑动、脚部）；`卡名 › 局名 ▾` 开当前局的 sheet（人设、写法、Timeline、Inspector 四项）；Status 图标开读数（demo 用 toast）。抽屉里切局或点新建，抽屉关闭。

## 约束

1. **一个语法。** 左右两侧折叠是同一个按钮形态、同一个过渡、同一种记忆方式。两层的顶条和脚部是同一块 DOM，只有中段是两份。
2. **不画**：卡头下的 summary、人设和写法在左栏的任何形态、故事行上的星标和 ⋯、独立主页、图标轨。开局页和详情页只画标题与返回的占位。
3. **数据有界，只有搜索结果可能很长。** 卡列表与故事列表各自滚动，脚部与顶条钉住。局名、卡名截断不换行。
4. **组件库是平台**：`<dialog>` 做抽屉和 sheet，popover、原生滚动、CSS 过渡；不用库。控件旁不放说明文字，用 aria-label；图标标 Phosphor 的名字，demo 里内联简单 SVG；数字等宽。
5. **词汇**：Card、Story（局）、Shelf（卡架，层 A）、Workspace（单卡工作区，层 B）、Strip（顶条）、Collapse、Drawer（手机抽屉）、Sheet、Persona、Writing、Timeline、Inspector、Status。不用"会话"、"聊天"。

## 空间层级与交互框架定稿（2026-10-31）

在原型走查后，放弃原先“左栏｜舞台｜右栏三列平铺、两侧顶角互扔折叠按钮”的平面做法，桌面端整体改为**三层立体空间层级**，以下产品语义作为原型与生产共同对齐的方向：

1. **三层立体空间关系**
   - **底层副空间（负空间）**：承载全局导航与外围壳层。包含左栏的双层导航（所有卡片 ↔ 单卡工作区），以及顶部极窄的全局壳层条（最左端固定一枚侧栏收展入口，右侧展示当前在读局的上下文锚点；当主舞台切去卡片详情、开局、时间线、检查器或写法页时，点击该锚点可直接回到阅读器）。
   - **主体实体卡片（正空间主舞台）**：右侧作为一张完整的独立实体卡片，承载阅读器或各全幅功能页，默认吃满除左栏外的全部横向空间，不再被常驻的第三栏挤压。
   - **上层临时挂载卡（右栏读数与指标）**：状态与指标面板默认不占用版面，仅在玩家主动唤出时从右侧临时挂载浮出（偏窄形态）。展开时对底层主舞台做虚化遮罩，将视觉焦点聚拢在当前读数与指标上，点击遮罩或关闭即可收起。

2. **左栏收展、正负空间反转与拖拽手感**
   - **彻底收起与宽度归零重置**：无论点击左上角收展入口、直接单击主卡片左缘分界线，还是将分界线向左拉过闭合阈值，左栏都会完全收起（不留图标轨），主卡片向左压满全屏。**任何收起动作都会清空此前临时拉宽或拉窄的宽度状态**；下一次无论以何种方式唤出左栏，一律回到居中、最适宜的默认宽度。
   - **正负空间反转（边缘浮出与原位落锁）**：左栏收起后，鼠标贴近屏幕最左缘时，原本属于底层负空间的左栏反转为上层正空间卡片，以默认宽度浮在主舞台之上；此时若点击左上角收展入口，浮出卡直接在原位降回底层负空间，主舞台左缘同步退让至同一默认宽度，完成层级交替。
   - **有界阻尼拖拽与阶梯闭合**：左栏展开时，主卡片左缘支持在默认宽度两侧的合理区间内拉拽微调。向内拉窄越过最小宽度后，会先经历一段有明显阻力的阶梯顿挫感，继续向左拉穿阈值才平滑合拢，避免误触或生硬吸附。

3. **阅读器正文与底部输入框宽度解耦**
   - 底部输入框保持独立、紧凑的适度宽度上限，作为页面下方的视觉锚点。
   - 上方正文区域不再受输入框宽度限制，随主舞台可用宽度自适应舒展；在拖拽分界线或收展左栏时，正文随宽度变化自然、跟手地单向折行重排，让释放出来的横向空间真正转化为更舒展的阅读行宽。
